# Database contract

Migration uses auth.users as identity source; all child rows cascade on account deletion. UUID ids generated by database. All public tables enable RLS; authenticated policies require auth.uid() = user_id for USING and WITH CHECK. No anonymous table access. Grant only necessary operations.

- preferences: user_id UUID PK/FK, data JSONB containing shared Preferences, updated_at timestamptz.
- tasks: id UUID PK, user_id UUID FK, title text (1..200), kind enum-like checked text, duration_minutes integer (5..1440), priority checked text, start_at/end_at/due_at timestamptz nullable, splittable boolean, recurrence checked text, status checked text default pending, created_at/updated_at timestamptz. Fixed tasks require start/end and end > start. Unique (user_id,id). API maps snake_case to shared camelCase.
- notification_records: id UUID, user_id FK, task_id, scheduled_at timestamptz, status pending/sent/cancelled/failed, version integer; unique(task_id,version,scheduled_at), composite FK(user_id,task_id) to tasks(user_id,id). Phase 1 schema only, no sending.
- request_keys: user_id, key, payload_hash, response JSONB, created_at; PK(user_id,key). Used for task-create idempotency, with transactional database RPC where appropriate.
- rate_limit buckets: database-backed authenticated mutation rate limit; deny client direct access and expose narrowly scoped RPC checking auth.uid(). Auth endpoints need host-level protection for distributed brute force; document local limiter limitation.

Do not store raw plans. Date validation and preference schema enforced at API; SQL checks provide defense in depth. Provide executable SQL isolation tests for configured local Supabase, and distinguish them from locally executed unit tests.

## Operational limits

Pre-authentication rate limits are per process/IP and require trusted proxy headers and deployment edge rate limiting. The durable mutation limit applies to application API writes; direct Supabase REST still relies on RLS/SQL constraints. Real SQL tests require a configured disposable database.
